# Руководство оператора (RU)

`mdmdoc` — твой локальный валидатор банковских документов и W-9/W-8 форм.
Всё происходит на твоих машинах: документы никуда не уходят, модели крутятся
на mac mini, полные номера счетов/SSN никогда не сохраняются на диск.

## 1. Установка и первый запуск (один раз)

```bash
cd ~/Projects/mdm-doc-validator
uv tool install --editable .        # команда mdmdoc доступна из любой папки
mdmdoc doctor                       # туннель к mini, модели, tesseract — всё ли на месте
```

`doctor` должен показать `ollama: OK … SSH tunnel -> mac-mini` и три модели
(TEXT/VISION/EMBED). Если mini выключен — включи его; туннель поднимется сам.

## 2. Веб-консоль — работает ПОСТОЯННО

Сервер установлен как LaunchAgent (`com.egor.mdmdoc`): стартует при входе в
систему, сам перезапускается при падении. Просто открой
`http://127.0.0.1:8766/ui` (или набери `mdmdoc ui` — откроет браузер).

```bash
./scripts/install-launchagent.sh    # переустановить агент (после переноса проекта)
launchctl unload ~/Library/LaunchAgents/com.egor.mdmdoc.plist   # остановить насовсем
tail -f ~/Library/Logs/mdmdoc-server.log                        # лог сервера
```

Страницы:

- **Dashboard** — статус модели/туннеля, drop-zone, последние прогоны.
- **Training** — разметка/метрики/обучение.
- **Debug** — doctor, задачи, логи сервера, размеры хранилища.

## 2.5 Качество, время и полные значения

- **Оценка времени** показывается до/в начале анализа (первая строка лога job,
  `estimate_s` в API): цифровой PDF ~20-60с, скан/фото ~1.5-3 мин, «thorough» и
  SAP-сравнение добавляют время. Оценка самообучается на прошлых прогонах.
- **Банковские реквизиты показываются ПОЛНОСТЬЮ** (счёт, обе ABA, IBAN) — чтобы
  сверять с формой глазами. **TIN/SSN/EIN всегда маской** — это не отключается.
  В обучающие примеры полные значения не попадают никогда.
- **Двухуровневая модель**: быстрый прогон — наша mdmdoc-extract; при пробелах
  (US-письмо без routing, W-9 без TIN, расхождения) автоматически подключается
  сильная qwen3:14b (бейдж «strong tier» на странице прогона). Галка
  **thorough** на Dashboard — сразу сильный уровень.
- **Подпись проверяет vision-модель** по картинке страницы (подпись — пиксели,
  не текст): рукописная подпись/печать = yes; typed-блок офицера = no + заметка
  BNK-026 (для американских писем это норма, не блокер).

## 3. Прогон документа

1. На Dashboard выбери класс: **Bank document** или **W-9 / W-8**.
2. Перетащи PDF/фото в рамку (или кликни и выбери файл). Языки любые — испанский,
   немецкий, китайский; многостраничники и повёрнутые фото обрабатываются.
3. Идёт живой лог (~15 сек для цифрового PDF, 1–3 мин для скана/фото).
4. Открывается страница прогона:
   - **вердикт** (зелёный ACCEPT / красный REJECT / жёлтый WARNING / синий
     NEED_MANUAL_REVIEW) и «что делать дальше»;
   - **предпросмотр страниц** документа (клик — полный размер);
   - **EXTRACTED DATA** — чистые данные документа (номера маскированы);
   - **Findings** — какие правила сработали и почему;
   - сырые артефакты — в аккордеоне внизу.

То же из терминала: `mdmdoc check-bank <файл>`, `mdmdoc check-w9 <файл>`
(`--lang ru` — сообщения правил по-русски, `--json` — машинный вывод).

## 4. Сравнение с SAP

Пока интеграции с BTP нет, SAP-сторона берётся со **скриншота** экрана
Bank Details (⌘⇧4 в SAP GUI/Fiori):

- сразу: на Dashboard нажми «+ SAP screenshot (optional)» перед прогоном;
- позже: на странице прогона — кнопка **Compare with SAP…** (документ
  прогонится заново вместе со скриншотом — полные значения живут только в
  памяти прогона, поэтому «доклеить» сравнение задним числом нельзя).

В отчёте появится таблица SAP COMPARISON: match / MISMATCH (с позицией
расхождения) / only-one-side. Умеет: ведущие нули SAP в Bank Account,
XXX-суффикс SWIFT, проверку Bank Key внутри IBAN. MISMATCH по счёту/IBAN/
стране = CRITICAL → NEED_MANUAL_REVIEW: не проводи, разбирайся.

CLI: `mdmdoc check-bank <док> --sap <скриншот>`.

## 5. Поправка (обучение) — одна кнопка, эффект сразу

Каждый промах превращай в учебный пример. Нажатие **Save & retrain** делает ВСЁ:

1. На странице прогона нажми **Correct — teach the model**.
2. Поправь что нужно (поля / doc_type / verdict / заметка). Чувствительные
   поля: «keep as shown» / «replace» (полное значение — сохранится маской) / «clear».
3. **Save & retrain** — дальше автоматически:
   - поправка сохраняется как учебный пример (маскированный);
   - пересобираются few-shot примеры промптов;
   - **пересобирается наша кастомная модель `mdmdoc-extract`** на mini;
   - документ перепроверяется — ты сразу видишь новый вердикт.
4. Твой вердикт становится **прецедентом**: для ЭТОГО документа (по хешу
   содержимого) он теперь всегда перекрывает машинный — на странице появится
   бейдж «operator override», в отчёте — заметка OPERATOR-1 с твоим комментарием.
   Похожие документы улучшаются через few-shot/модель (не мгновенно, но с каждым
   примером лучше).

Повторная поправка заменяет старый пример. Прецеденты действуют в обычных
прогонах, но **не в eval** — метрики всегда меряют «голую» модель, иначе они бы
завышались твоими же ответами. Терминал: `mdmdoc review last --open`
(few-shot пересобирается автоматически и там).

### Пакеты документов (Welcome Packet и т.п.)

Если в пакете есть страница-инвойс И банковское письмо (например, account
confirmation letter от банка на стр. 3) — пакет классифицируется по ПИСЬМУ,
инвойс его не отравляет. Страницы с письмом получают приоритет в анализе;
в предупреждениях будет видно, по какой странице принято решение.

## 6. Тренировка и метрики

Страница **Training**:

- **Build few-shot** — вшивает лучшие исправления в промпты (работает уже с
  5–10 примеров). После этого запусти eval и посмотри дельту.
- **Run eval** (с тегом, например `after-fix-w9`) — прогоняет ВЕСЬ размеченный
  корпус заново (минуты!), пишет метрики: точность типа документа, вердикта,
  по-полевые точности, **leakage (обязан быть 0)**. История с графиками-спарклайнами.
- **Build Modelfile** (+apply) — собирает кастомную модель `mdmdoc-extract`
  на mini (потом `export MDMDOC_TEXT=mdmdoc-extract`).
- **LoRA** — только когда наберётся 100+ примеров (см. TRAINING.md).

Правило: меняешь одну вещь → eval с тегом → сравнил → оставил или откатил.
Не делай выводов по разнице в один документ.

## 7. Отладка

- **Debug-страница**: doctor целиком, задачи, последние строки лога, размеры
  `runs/`/`inbox/`.
- Mini недоступен → включи его; `mdmdoc doctor` покажет, поднялся ли туннель.
  Сервер сам перепроверяет хост перед каждой задачей.
- Артефакты прогона: `runs/<id>/` — `stage_a.json` (что распозналось),
  `extraction.json` (что смапилось), `findings.json` (какие правила сработали).
  Смотри их в этом порядке, чтобы понять, на каком слое промах.
- Правила меняются в `rules/banking.yaml` / `rules/w9.yaml` обычным текстом.

## 8. FAQ

**PDF под паролем?** Вердикта не будет — exit 4 / понятная ошибка. Запроси
незапароленную копию.

**Чем WARNING отличается от NEED_MANUAL_REVIEW?** WARNING — использовать можно,
но с оговоркой (нет подписи, документ старше 2 лет). NEED_MANUAL_REVIEW —
руками не трогать, пока не разберёшься (несовпадение с SAP, битые реквизиты,
внутренние противоречия W-9).

**Как удалить документ полностью?** `inbox/<sha16>__имя`, папка `runs/<sha16>/`
и (если размечал) строка с этим `doc_sha256` в `dataset/labels.jsonl`.

**Кривое фото?** Поворот определяется автоматически (OSD). Если совсем мыло —
пере сфотографируй ровнее; вертикальные строки лога `stage_a.json` покажут,
что удалось прочитать.

**Порт занят?** Дефолт 8766 (8765 занят Anki). `mdmdoc ui --port 8777`.

**Инвойс приняло как банковское подтверждение?** Не должно никогда (правило
BNK-001, метрика invoice_false_accept = 0). Если случилось — это баг: размети
через review и сообщи (скилл mdmdoc-improver знает, что делать).
